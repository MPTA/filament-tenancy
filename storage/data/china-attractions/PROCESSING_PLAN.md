### مرحله 4: تشخیص نوع جاذبه (Attraction Type Detection)

**⚠️ مرحله جدید - تشخیص خودکار نوع با الگوریتم هوشمند**

بر اساس `AttractionTypeEnum`:
- `natural` - طبیعی
- `cultural` - فرهنگی
- `man_made` - ساخته دست بشر
- `leisure` - تفریحی
- `sport` - ورزشی
- `events` - رویدادها
- `uncategorized` - دسته‌بندی نشده

**الگوریتم تشخیص:**

```python
# سیستم امتیازدهی با وزن‌های مختلف:

1. نام چینی (وزن: 3x) - بالاترین اعتبار
2. نام انگلیسی (وزن: 2x) 
3. توضیحات چینی (وزن: 1x) - فقط 200 کاراکتر اول
4. توضیحات انگلیسی (وزن: 0.5x)

# کلمات کلیدی با اولویت‌های مختلف:

🟢 اولویت بالا (+10 امتیاز):
natural: 山،湖，江，河，峰，岛，滩，海，峡谷，森林，瀑布
cultural: 博物馆，寺，庙，塔，古迹，遗址，故宫，宫，殿
man_made: 城墙，长城，广场，街道，建筑，大厦，桥
leisure: 游乐园，主题公园，水族馆，动物园
sport: 滑雪场，体育场，体育馆
events: 演出，表演，剧场，剧院

🟡 اولویت متوسط (+5 امتیاز):
natural: 风景区，自然，生态
cultural: 文化，艺术，纪念
man_made: 中心，区域
leisure: 娱乐，休闲
sport: 运动，体育
events: 活动，节庆

🔵 اولویت پایین (+2 امتیاز):
natural/leisure: 公园 (پارک - نیاز به تحلیل بیشتر)

# الگوهای ویژه (بالاترین اولویت):
"(国家|森林|自然|生态|风景)(公园|保护区)" → natural
"(主题|游乐|欢乐|水上)(公园|乐园)" → leisure

# قانون نهایی:
if امتیاز بالاترین نوع < 5:
    type = "uncategorized"
else:
    type = نوعی که بالاترین امتیاز را دارد
```

**نمونه نتایج:**

```python

"八达岭长城" → man_made (长城=10, 城=10 → score=60)  
"北京动物园" → leisure (动物园=10 → score=30)
"香山公园" → natural (山=10, 公园=2 → score=36)
"五道营胡同" → uncategorized (امتیاز کم)

- Leisure: 2.8% (36 جاذبه)
- Events: 0.4% (5 جاذبه)
- Sport: 0.1% (1 جاذبه)
```

**موقعیت فیلد:**

### مرحله 9: استخراج Sub-Attractions با AI

**استراتژی هوشمند:**

1. **تحلیل با Claude AI:**
   - بررسی description چینی
   - شناسایی نام‌های خاص مکان‌های فرعی
   - تشخیص: سالن‌ها (殿،馆)، معابد (寺،庙)، برج‌ها (塔)، باغ‌ها (园)، دریاچه‌ها (湖)

2. **فیلترهای کیفی:**
   - طول نام: 2-8 کاراکتر چینی
   - بدون کلمات توصیفی: 位于،设有，建有，可以，还有
   - بدون افعال یا صفات
   - فقط اسامی خاص مکان‌ها

3. **الگوهای معتبر:**
   ```
   ✅ معتبر: 太和殿，珍宝馆，昆明湖，白塔
   ❌ نامعتبر: "位于北方"، "设有展览"، "可以参观"
   ```

4. **استخراج قیمت sub-attraction:**
   
   **⚠️ قوانین دقیق استخراج قیمت ساب‌اترکشن:**
   
   ```python
   # جستجو در ticket_info برای نام ساب‌اترکشن
   مثال: "珍宝馆票成人票 ¥125" یا "珍宝馆门票 ¥125"
   
   ✅ قیمت‌های معتبر:
   - "珍宝馆票 ¥125" → local_price: 125.0
   - "太和殿门票成人票 ¥80" → local_price: 80.0
   
   ❌ قیمت‌های نامعتبر (بدون local_price):
   - قیمت ترکیبی: "珍宝馆+钟表馆 ¥150" → بدون قیمت
   - قیمت با تور: "珍宝馆+讲解 ¥200" → بدون قیمت
   - قیمت نامشخص → بدون قیمت
   
   قانون: فقط اگر قیمت ورودی جداگانه برای ساب‌اترکشن وجود دارد
   ```

5. **خروجی:**
```json
"sub_attractions": [
  {"name": {"zh_CN": "太和殿"}},
  {"name": {"zh_CN": "珍宝馆"}, "local_price": 125.0}
]
```

   **نکته:** اگر ساب‌اترکشن قیمت جداگانه ندارد، فیلد `local_price` اصلاً اضافه نمی‌شود.

- با null در فیلدهای nullable (local_price، فیلدهای فصلی)
- با قیمت استاندارد (بزرگسال)
- با sub-attractions معتبر
- با نوع جاذبه تشخیص داده شده (type field)
- آماده Import به PostgreSQL

## مثال دستور کاربر

برای شروع، کاربر می‌گوید:

```
"شهر Shanghai را پردازش کن"
```

AI پاسخ می‌دهد و فایل `shanghai.json` می‌سازد.
